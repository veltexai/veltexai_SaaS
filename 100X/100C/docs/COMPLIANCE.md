# 100C outbound compliance gate

Every real Instantly run now fails closed unless the deployment provides an approved sender identity,
physical postal address, HTTPS unsubscribe endpoint, verified SPF/DKIM/DMARC, and verified one-click
unsubscribe support. The same gate applies to the 100G automated path before it can create a lead.

Required Vercel environment variables (values are deployment secrets/configuration and must never be
printed in logs):

```text
VELTEX_100C_COMPLIANCE_APPROVED=true
VELTEX_100C_SENDER_NAME=<approved sender name>
VELTEX_100C_FROM_EMAIL=<authenticated sender address>
VELTEX_100C_REPLY_TO=<monitored reply address>
VELTEX_100C_POSTAL_ADDRESS=<valid physical postal address>
VELTEX_100C_UNSUBSCRIBE_URL=https://<domain>/<unsubscribe-path>
VELTEX_100C_SPF_DKIM_DMARC_VERIFIED=true
VELTEX_100C_ONE_CLICK_UNSUBSCRIBE_VERIFIED=true
```

The pilot endpoint path is `/api/unsubscribe`. It requires a signed, expiring token generated by the
outbound-mail integration; never place an email address directly in the URL. Migration
`013_public_unsubscribe.sql` must be applied before the endpoint can record opt-outs.

The final campaign must also be reviewed for accurate headers and subject lines, relevant and
verifiable recipients, and content that clearly identifies the commercial purpose. Suppression,
reply-intelligence, duplicate, bounce, complaint, customer/trial, account-health, webhook, and ramp
controls remain independent and cannot be bypassed by this configuration.

Migration `012_compliance_control_plane.sql` adds durable evidence records, append-only control audit
events, global/new-audience/copy-change pause controls, and a human review queue. It is additive and
does not enable sending. The preflight evaluator treats any missing evidence or active pause as a
blocking condition.

The internal compliance preflight endpoint reports pass/fail checks without exposing secret values.
Keep `VELTEX_100C_GLOBAL_SEND_PAUSE=true` available as an incident control; it blocks all real
Instantly runs immediately.

Before enabling these flags, verify the DNS records and one-click behavior in the sending provider and
have the final workflow reviewed for applicable federal and state requirements. This gate is an
engineering control, not legal advice or a guarantee of deliverability.
