# R2 production reconciliation — G3

This directory builds the production-specific migration plan required by G3.
It is deliberately split into discovery, planning and execution so that a
29-row migration history can never be mistaken for proof that later schema
effects are absent.

## Safety contract

- Production is `iwoaaljitifloolszxlu` and every other project ref is refused.
- The committed discovery query is read-only.
- No customer content, email address, tracking token or credential is selected.
- The plan builder requires a separate independent-review record whose
  SHA-256 binds the exact fingerprint bytes.
- Migration source hashes are compared with the checked-in, ordered
  `reviewed-source-sha256.json`; they are not accepted merely because they
  match whatever happens to be on disk at build time.
- Generated SQL is written only below `/private/tmp` and is **unarmed**. It
  begins with an unconditional exception and cannot mutate any database.
- A separate arming step is intentionally not implemented. It may be added
  only after G2 backup evidence, exact-artifact independent review, G4 founder
  acceptance and action-specific production authorization.

## Workflow

1. Run `00-read-only-production-fingerprint.sql` in the production SQL editor.
2. Save only its redacted result into a copy of
   `production-fingerprint.template.json`; never save row content.
3. Independently review the exact fingerprint and create a separate review
   record containing `status`, `reviewer`, `reviewed_at`, and the exact
   `fingerprint_sha256`.
4. Build the unarmed plan:

   ```sh
   node quality/r2-production-reconciliation/build-production-plan.mjs \
     /private/tmp/veltex-r2-production-plan \
     /path/to/reviewed-fingerprint.json \
     /path/to/independent-review-record.json
   ```

5. Validate it:

   ```sh
   node quality/r2-production-reconciliation/validate-production-plan.mjs \
     /private/tmp/veltex-r2-production-plan
   ```

The current plan remains deliberately unarmed. Claude's review of `bdd43c1`
proved that the first-generation boolean probes are not strong enough to
authorize `reconcile-history`, especially for migration 040 and the location
pricing seed. The next revision must replace them with complete structured
`absent / complete / partial` vectors, with partial always refused, before any
arming implementation exists. R2 migrations are never eligible for
history-only reconciliation: they must be exhaustively absent and then applied
in source order.

The SQL artifact stores the manifest as Base64 in a single line and the
validator requires the exact generated bytes. Raw fingerprint-controlled JSON
is never interpolated into an executable block comment.

## Authorized production bundle gate

`build-authorized-production-bundle.mjs` is a separate post-G4 armer. It
requires the exact reviewed manifest, reviewed fingerprint, final no-drift
fingerprint and founder-authorization record. It refuses any binding or source
change, strips only exact outer migration transaction wrappers, emits one outer
transaction, records each of the 35 history rows once, and places its critical
history/count/organization/R0/tracked-link/PG17 privilege assertions before the
single commit.

The presence of an armed local artifact is not proof that it is safe to paste.
`r2:test-authorized-production-bundle` must pass, the exact generated bytes must
pass a production-shaped execution/rollback test and independent review, and
the dashboard project must still be verified as `iwoaaljitifloolszxlu` before
execution. Generated SQL stays under `/private/tmp` and is never committed.
